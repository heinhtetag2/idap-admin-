# Architecture

## Tech stack

| Concern | Choice |
|---|---|
| Framework | **React 18.3** (function components + hooks) |
| Language | **TypeScript 5.9**, strict mode, `@/*` → `src/*` path alias |
| Build/dev | **Vite 6** + `@vitejs/plugin-react` |
| Routing | **react-router v7** (`createBrowserRouter`) |
| Server state | **TanStack Query v5** (provider mounted; see [what's wired](#what-is--isnt-wired)) |
| Client state | **Zustand v5** (survey-category store, persisted) |
| Forms / validation | **react-hook-form** + **zod** + `@hookform/resolvers` (deps present) |
| UI primitives | **Radix UI** wrapped under `src/shared/ui`, **lucide-react** icons |
| Styling | **Tailwind CSS v4** (`@tailwindcss/vite`) + `tw-animate-css`, `clsx` + `tailwind-merge` via `cn()` |
| Animation | **motion** (Framer Motion) — page transitions, drawers, modals |
| Charts | **recharts** (dashboard) |
| Drag & drop | **@dnd-kit** (survey-builder question reorder) |
| i18n | **i18next** + **react-i18next** |
| Dates | **date-fns** |
| Mock API | **MSW 2** (installed, dev-only, currently no handlers) |

## Boot sequence

[`src/main.tsx`](../src/main.tsx):

```
main.tsx
 ├─ createQueryClient()
 ├─ if (DEV && VITE_USE_MOCK_API)  → start MSW worker (onUnhandledRequest: 'bypass')
 └─ render
     └─ QueryClientProvider
         ├─ <App/>  → RouterProvider(router)
         └─ <ReactQueryDevtools/>  (dev only, collapsed)
```

[`src/app/App.tsx`](../src/app/App.tsx) just renders `RouterProvider`; it also imports `./i18n` for its init side-effect.

### FSD dependency rule

A layer may import only from layers below it: `app → pages → widgets → features → entities → shared`. All cross-layer imports use the `@/*` alias, e.g. `import { Sidebar } from '@/widgets/sidebar'`, `import { cn } from '@/shared/lib/cn'`.

Note: `features/` and `entities/` exist as empty placeholders. Today **page-specific types and demo data live in co-located `*-data.ts` files** (e.g. `pages/companies/company-data.ts`) rather than in `entities/`. See [conventions.md](conventions.md).

## Routing

Defined in [`src/app/routes.ts`](../src/app/routes.ts). Two public routes sit outside the shell; everything else is nested under `Layout` (which enforces auth).

| Path | Component | Notes |
|---|---|---|
| `/login` | Login | public |
| `/forgot-password` | ForgotPassword | public |
| `/` and `/dashboard` | Dashboard | index route |
| `/surveys` | Surveys | list / moderation |
| `/surveys/new` | SurveyBuilder | create |
| `/surveys/:id` | SurveyDetail | detail + responses |
| `/companies` · `/companies/:id` | Companies · CompanyDetail | |
| `/respondents` · `/respondents/:id` | Respondents · RespondentDetail | |
| `/reports` | Reports | accepts `?companyId=` scope |
| `/billing` | Billing | |
| `/payouts` | Payouts | |
| `/help` | Help | |
| `/settings` | Settings | |
| `*` | NotFound | 404 |

> The live app routes are **flat** (`/companies`, `/surveys/:id`, …). The portal-namespaced paths in `shared/config/routes.ts` (`/admin/...`, `/client/...`) are a separate, aspirational source of truth and are **not** what the router actually uses today.

### Layout & navigation

[`src/app/Layout.tsx`](../src/app/Layout.tsx) renders the [`Sidebar`](../src/widgets/sidebar/Sidebar.tsx) + a `motion`-animated `<Outlet/>` (fade/slide on route change). The sidebar groups nav into **Overview / Users / Content / Moderation / Payments / Account**, plus a bottom strip with Help, a Notifications slide-out panel, and a profile menu (with Log out). It collapses to an icon rail.

## Auth

[`src/shared/lib/auth.ts`](../src/shared/lib/auth.ts) — a deliberately trivial demo gate backed by `localStorage` key `idap-admin-auth`:

```ts
isAuthed()  // localStorage[key] === '1'
signIn()    // set key = '1'
signOut()   // remove key
```

`Layout` redirects to `/login` when `!isAuthed()`. `Login`/`ForgotPassword` redirect to `/` when already authed. **There is no real authentication, token, or user identity** — any credentials succeed, and the "current admin" (*Hein Htet*) is hardcoded in several components.

## State management

- **Server state — TanStack Query.** The provider is mounted and [`createQueryClient()`](../src/shared/lib/query-client.ts) sets sensible defaults (`staleTime: 30s`, `gcTime: 5m`, `retry: 1`, `refetchOnWindowFocus: false`). **No queries/mutations are actually defined yet** — pages read from co-located demo arrays.
- **Client state — Zustand.** One store: [`useCategoryStore`](../src/shared/config/categories.ts), persisted to `localStorage` under `idap-survey-categories`. It is the single source of truth for survey categories, consumed by both Settings → Categories and the Survey Builder.
- **Local UI state — `useState`/`useMemo`.** Filters, search, tab selection, drawer/modal open state, optimistic status changes, and demo mutations all live in component state and reset on reload.

## Mock API (MSW)

MSW is configured to run **only in dev with `VITE_USE_MOCK_API=true`**, and starts with `onUnhandledRequest: 'bypass'`. The handler list in [`handlers.ts`](../src/shared/api/msw/handlers.ts) is **empty**, so MSW currently intercepts nothing — it's scaffolding for when a real API is introduced.

## Internationalization

[`src/app/i18n.ts`](../src/app/i18n.ts) initialises i18next with inline `resources` for **en / es / fr / ko**, `lng: 'en'`, `fallbackLng: 'en'`, `escapeValue: false`. Components call `useTranslation()` and wrap user-facing strings in `t(...)`. Language is switchable at runtime from **Settings → Language & region** via `i18n.changeLanguage()`.

> Note the env default `VITE_DEFAULT_LOCALE=mn` (Mongolian) is **not** honored by `i18n.ts`, which hardcodes `lng: 'en'`. See [conventions.md](conventions.md#known-inconsistencies).

## Theming & design system

- **Tailwind v4**, configured CSS-first. [`src/styles/index.css`](../src/styles/index.css) imports `fonts.css`, `tailwind.css`, `theme.css`.
- **Font:** Space Grotesk for both `--font-sans` and `--font-serif`.
- [`theme.css`](../src/styles/theme.css) defines a full token set in **OKLCH** under `:root` and a `.dark` override, mapped to Tailwind via `@theme inline`. Radius default `--radius: 0.875rem`.
- **In practice, most components hardcode hex colors** rather than using the theme tokens. The de-facto palette:

| Role | Value |
|---|---|
| Brand / accent | `#FF3C21` (orange-red) |
| Text | `#1A1A1A` |
| Muted text | `#8A8A8A`, `#4A4A4A` |
| App background | `#FAFAFA` |
| Surfaces / borders | `#FFFFFF` / `#E3E3E3`, `#F3F3F3` |
| Success (approved/paid) | `#047857` on `#ECFDF5` |
| Warning (pending/warned) | `#B45309` on `#FFFBEB` |
| Danger (rejected/suspended/failed) | `#B91C1C` / `#DC2626` on `#FEF2F2` |
| Info (processing/completed-blue) | `#1D4ED8` on `#EFF6FF` |

A dark-mode token set exists but there's no theme toggle wired in the UI.

## What is / isn't wired

Because this is a prototype, be explicit about the boundary:

**Real:** routing, navigation, layout/animation, i18n switching, the persisted survey-category store, all filtering/search/sorting/pagination logic, CSV export (client-generated), and the demo auth gate.

**Mocked / not persisted:**
- All entity data is in-memory demo arrays (`pages/*/**-data.ts`); edits and status changes vanish on reload.
- No backend calls — TanStack Query and MSW are scaffolding only.
- Auth accepts anything; "current admin" is hardcoded.
- Most Settings "Save" buttons and Billing purchases are UI-only.
- Respondent profiles shown in the response drawer are **deterministically generated from a seed string**, not stored records.
